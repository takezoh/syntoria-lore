## Post-deploy observations — private services

The migration Job execution `thymesis-neon-migrate-526m8` succeeded in 9.68 seconds. It reapplied all 39 migrations, confirmed the app and worker roles remained non-bypass, confirmed worker membership, and verified helper schema `CREATE` was revoked with non-inheriting memberships and at least one `SET`-capable membership per helper role.

The ledger reconcile execution `thymesis-ledger-reconcile-bbrl9` succeeded in 13.73 seconds. It reported `already-current`, replayed 0 records, purged 0 records, and kept readiness `ready`; no bootstrap or Head recreation ran.

Private API revision `thymesis-api-00001-d55` and worker revision `thymesis-worker-00001-6h9` were deployed. Anonymous requests to both services returned HTTP 403, and authenticated readiness requests returned HTTP 200. The worker's custom-audience readback exactly matched the canonical project-number URL; its service-level `run.invoker` bindings are the task and Scheduler service accounts. Existing operator access is inherited at project scope; no operator service-level binding was added. Queue readback matched the declaration: 2 concurrent dispatches, 2 dispatches per second, 5 attempts, 3600-second retry window, and 10–300-second backoff. Scheduler is enabled for the minute sweep; its last-attempt status was successful, and two observed `POST /internal/dispatch/sweep` requests from `Google-Cloud-Scheduler` returned HTTP 200 with latencies 0.4293 and 0.6602 seconds. This verifies authenticated Scheduler-to-worker delivery. A real Cloud Tasks `job_id` delivery through to a terminal database state remains unobserved.

The public identity invocation approval request is still awaiting the user's response. Public API invocation has not been requested or attempted. Private revisions and readiness probes do not establish the public OAuth flow.

The deployed worker service account also passed the Vertex ADC smoke Job `thymesis-provider-verify-f7mqm` (exit 0, 23.56 seconds) using the same runtime image. The run returned one anchored proposal and a 1536-dimensional embedding from `gemini-embedding-001`, with extraction through `gemini-3.5-flash` in `asia-southeast1`. The temporary verification Job was deleted after completion. This validates the worker identity’s provider access, not extraction quality or cost.

The expanded read-only `cloud:verify-boundaries` gate passed against the project, all thirteen secret, four resource, eight service-account, ledger-bucket, artifact-bucket, worker-service, artifact-bucket-configuration, and custom-role readbacks. The eight declared service accounts have exactly the contracted direct project roles: API and worker have `roles/aiplatform.user`, build has `roles/logging.logWriter`, and the other five have none; the gate also checked the complete membership of the two declared project-role bindings while leaving other project roles untouched. The four active project custom roles matched their exact declared permissions: ledger Head (`storage.objects.create`, `delete`, `get`), immutable ledger nodes (`create`, `get`), artifact reader (`get`), and artifact worker (`create`, `delete`, `get`, `list`).
