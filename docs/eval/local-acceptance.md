# Local acceptance record — 2026-10-14

This dated record lists the local implementation checks that were executed against the [product requirements](../design/requirements.md) and the contracts in [ARCHITECTURE](../../ARCHITECTURE.md), with their results and limits. It is evidence from the approved local test environment only. It does not declare a GCP/Neon release decision or G0–G4 production acceptance; hosted status is in the [cloud verification register](cloud-verification.md).

## Method

The checks ran on 2026-10-14 against one local Compose stack, kept separate from an unrelated PostgreSQL test container, with PostgreSQL at `127.0.0.1:55433` and the Node container running as a non-root user. Because the host's Docker daemon rules required standalone invocations, each runner of `sh scripts/local.sh acceptance` was executed directly against that stack: build, migration reapplication, typecheck, lint, format, unit and PostgreSQL integration tests, restore clone, separate-database portability import, OpenAPI snapshot, secret scan, dependency audit, REST/MCP smoke, real-worker recovery and Forget, the 231-case evaluation, mixed load, and token and memory checks after stop and restart. Hosted CI was not run. How to rerun is in [development](../development.md#acceptance-and-release).

The 1.0 here is a contract regression result using artificial fixtures and the deterministic local-hash embedding and local curator. It does not represent a human-labeled answer set, semantic quality on natural conversation, a paid-model comparison, production Recall@5 quality or cost savings. The summary baseline is likewise a fixed-input control implementation, not an LLM summary. No attainment of product targets or capacity is inferred.

v7 includes a regression that places, in the same scope, a query about a proposal that was private at a past point in time and an unrelated active procedure that shares only the same opaque hexadecimal identifier. With lexical support that excludes the hex identifier, the query resolves to unknown, while the exact statement, explicit memory/subject ID and authorized relation candidate paths are preserved. Ordinary conditions and short technical terms, such as numeric-only dates and quantities, `v2` or `HTTP500`, are outside the opaque-ID rule. This regression tests the boundary of the deterministic local matcher and does not show the semantic quality of a paid model.

## Verification limits

- The curator and embedding providers were deterministic local fixtures. Evaluation scores are contract regressions, not semantic quality, paid-model behavior, production Recall@5 or cost savings.
- The issuer, task sender, scheduler, filesystem deletion ledger and export store were local adapters. They do not establish cloud identity, Cloud Tasks delivery, managed key custody, object-store durability, Neon backup retention or RPO/RTO.
- The fresh-database import used separate databases in the same local PostgreSQL cluster, not a separate server, cluster or cloud.
- The load smoke is not capacity or SLO evidence for 100k/1m memories or 500k/5m evidence references.
- No hosted CI result is included.
